# Installation

[← Home](https://github.com/SyntaxDevTeam/PlotsX/blob/main/docs/wiki/en/Home.md)

PlotsX is installed on the server. Players do not need to add anything to their Minecraft client.

## Prepare the server

You need a Paper server and a PlotsX build compatible with its version. The plugin is built for Java 21; if your server build requires a newer Java version, use the version required by the server.

Versions recognized by the plugin include 1.20.6, 1.21–1.21.11, 26.1, 26.1.1, 26.1.2, 26.2, and 26.3. Recognizing a version number does not mean every possible plugin combination has been tested. PlotsX also declares Folia support — test your exact build on a staging server before opening it to players.

## Install PlotsX

1. Download the `.jar` file from [PlotsX releases](https://github.com/SyntaxDevTeam/PlotsX/releases).
2. Stop the server.
3. Place the file in the `plugins` directory.
4. Start the server and verify that PlotsX enables without errors.
5. Open `plugins/PlotsX/config.yml` and set the world name in `plots.world`.
6. Grant players the required [permissions](https://github.com/SyntaxDevTeam/PlotsX/blob/main/docs/wiki/en/Permissions.md).
7. After finishing the configuration, restart the server and test `/claim` with a regular player account.

The default SQLite database stores data locally. You do not need to create a separate database to get started.

## SQL backup

The `/ptx export [mysql|mariadb|sqlite|postgresql|h2]` command writes plots, segments and chunks, members, flags, history, the payment journal, identity aliases, and teleport points to `plugins/PlotsX/dump/backup.sql`. Without an argument it uses the syntax of the currently configured database. For example, `/ptx export mysql` prepares a backup for MySQL or MariaDB even if the server currently uses SQLite. Each successful export replaces the file, so move older backups elsewhere if you want to keep them.

`/ptx import` restores that file into the currently configured database and **replaces the current PlotsX data**. The backup syntax must match the target database engine. For a migration, first export using the target syntax, change the database configuration, restart the server, and then run the import. The import supports backups generated by this PlotsX version, not arbitrary SQL files. Import only trusted backups.

Perform backups and restores during maintenance, without players or other writes to the database. Keep a backup of the current database before importing. A data-loading failure rolls the transaction back; creating missing tables and resetting H2 counters are not part of that guarantee. After a successful import, the plugin refreshes its cache.

This is a PlotsX database backup, not a full server backup: copy worlds, configuration, and data from other plugins separately. These commands require `plotsx.cmd.ptx`.

## What about integrations?

Basic plots do not require WorldGuard or an economy plugin. Plot expansion is paid by default using the server economy: to use paid expansion, you need Vault or VaultUnlocked and an economy provider. You can also set expansion prices to `0`.

See [Integrations](https://github.com/SyntaxDevTeam/PlotsX/blob/main/docs/wiki/en/Integrations.md) and [Configuration](https://github.com/SyntaxDevTeam/PlotsX/blob/main/docs/wiki/en/Configuration.md).

Release 1.0.0 includes both classic and chunk-based plots. Before opening the server to players, test plot creation, container protection, and expansion.
