# PlotsX 1.0.0 — przygotowanie wydania

Data weryfikacji: 8 października 2026 r.

## Zakres wydania

Wydanie obejmuje działki klasyczne i chunkowe, zarządzanie członkami i rangami, prywatne pojemniki, flagi ochrony, rozszerzanie, granice, teleportację oraz publiczne API v2 dla Javy i Kotlina. README przedstawia plugin administratorom i graczom; wiki opisuje aktualne tryby i cenniki.

## Zamknięte problemy

- Oba typy rozszerzeń korzystają z `ExpansionPurchaseService` i trwałego dziennika. Geometria i `LAND_COMMITTED` są zatwierdzane w jednej transakcji. Błąd publikacji cache ani utracona odpowiedź po udanym commit nie uruchamiają zwrotu przyznanego terenu.
- Debit jest poprzedzony trwałym zapisem zamiaru. Nieudany zapis po potwierdzonym pobraniu uruchamia zwrot na zapisane konto, również po rozłączeniu gracza. Przerwanie serwera i niejednoznaczne odpowiedzi pozostawiają trwałe dowody do rozliczenia; dostawca nie jest ponawiany w ciemno.
- Dziennik zachowuje promień i współrzędne klasycznych segmentów. Migracja uzupełnia starszy schemat bez utraty operacji. Backup v6 obejmuje nowy format; import v1–v5 pozostaje obsługiwany. Nierozliczone importowane płatności trafiają do kwarantanny.
- Transfer własności przez komendy i `transferOwnershipAsync()` pobiera uprawnienia na wątku odbiorcy, a zapis wykonuje na workerze. Synchroniczne API zwraca `RECIPIENT_WRONG_THREAD` dla innego regionu Folii.
- Harness Paper kompiluje się z przeciążeniem `onReload()` dostępnym dla Javy i czeka na zakończenie asynchronicznego reloadu. Asercje rozróżniają zdrową publikację poprzedniego snapshotu od odmowy ochrony po błędzie.
- CI odczytuje wersje serwera z właściwej ścieżki, buduje oba harnessy i uruchamia macierz baz przed publikacją. WorldEdit 7.3.18 / WorldGuard 7.0.16 są bazą kompilacyjną zgodną z Javą 21; WorldEdit 7.4.5 wymaga Javy 25.

## Wykonana weryfikacja

`./gradlew clean build liveTestJar foliaLiveTestJar --offline` zakończył się sukcesem. Po końcowych zmianach ponownie wykonano build, kompilację harnessów i testy: **228 testów, 0 niepowodzeń, 0 błędów, 0 pominiętych**. Lokalna macierz SQL obejmuje SQLite i H2.

Testy płatności obejmują obie geometrie: odmowę ekonomii, niepewny debit, rollback przed commit, utraconą odpowiedź po commit, błąd publikacji cache, rozłączenie przed refundacją, nieudany/niepewny zwrot, ponowienie ID i konkurencyjne zakupy. Sprawdzono również limity klasycznych rozszerzeń, kolizje z chunkami, kształt L, rollback po błędzie dziennika i migrację/import starszych backupów.

## Aktualizacja i wycofanie

Przed aktualizacją zatrzymaj serwer i zachowaj wspólną kopię bazy, konfiguracji, danych pluginu i światów. Zainstaluj główny JAR, uruchom serwer i sprawdź migrację oraz działkę zwykłym kontem. Integracje powinny korzystać z API v2; na Folii transfer między regionami wymaga metody asynchronicznej.

Wycofanie do starszego RC wymaga odtworzenia kopii sprzed aktualizacji razem z odpowiednim JAR-em. Nie importuj backupu v6 do starszego pluginu. Przed przywróceniem rozlicz nierozstrzygnięte płatności z historią ekonomii, aby nie powtórzyć obciążenia lub zwrotu.

## Granice weryfikacji

MySQL, MariaDB i PostgreSQL zostały dodane jako usługi obowiązkowego zadania CI, ale nie były uruchomione w lokalnym przebiegu. Wynik zdalnego CI należy sprawdzić przed publikacją. Testy nie certyfikują każdej rozpoznawanej wersji serwera ani wszystkich kombinacji zewnętrznych dodatków. Rzeczywiści dostawcy ekonomii, WorldGuard/CoreProtect i wizualna obsługa wszystkich menu wymagają sprawdzenia na docelowym stagingu. Zewnętrzne rozliczenia o niejednoznacznym wyniku pozostają zadaniem administracji z trwałym dziennikiem operacji.
